# T3 Code instructions

These rules apply when the current session runs inside T3 Code.

## Workspace isolation

- Use one dedicated worktree per T3 thread that modifies repository files.
- Before the first edit or branch setup, check the thread's workspace binding.
- If already bound to a dedicated worktree, reuse it.
- If bound to the primary checkout, automatically create a worktree using T3's workspace tools.
- Move the current thread into that worktree before editing. Do not launch another thread unless requested.
- Verify that the thread binding and command working directory both point to the dedicated worktree before editing.
- Reuse that worktree throughout the thread, including follow-up changes, formatting, tests, commits, and PR updates.
- Do not create another worktree merely because another edit is requested.
- Do not edit or switch branches in the primary checkout unless explicitly instructed.
- Read-only investigations and reviews do not require a new worktree.
- If workspace setup fails, report the blocker before modifying files.
- Preserve existing uncommitted work. Never move, discard, or include unrelated changes.
- A shell `cd` or `git worktree add` does not update the thread's workspace binding.

## Browser

- Prefer T3's shared browser when available. Follow explicit requests for another browser.
- Open Hunkpad URLs in T3's shared browser when available.

## Code reviews

- Use the built-in diff view for routine reviews.
- For delegated reviews, use `isolation: "shared"`.
